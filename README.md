# Active Noise Control (ANC) Summer Research Project

***Note:Due to time constraints, this README contains AI generated summaries of work done in this project. All other files were created manually and verified by my supervisor.***

Real-time feedforward Active Noise Control using the Filtered-x (Normalized) LMS
algorithm, developed and tested on a Behringer UMC404HD audio interface with
multiple reference/error microphones and cancellation speakers.

## How it works (current system)

Feedforward ANC: a **reference mic** picks up the incoming noise before it
reaches the listening area, an adaptive FIR filter `W(z)` computes a
cancelling signal, and one or more **cancellation speakers** play it so it
destructively interferes with the noise at the **error mic(s)**. The filter
weights are updated every frame using FxNLMS, gradient-descent driven by the
residual error and a modeled "secondary path" `S_hat(z)` (the acoustic path
from each cancel speaker to each error mic).

## Pipeline

Run these in order:

1. **`pipeline/Impulse_response.m`** — plays a log sweep out of each
   cancellation speaker and records all error mics to measure the secondary
   path. Saves results to `pipeline/ImpulseResponses/`.
2. **`pipeline/Full_system.m`** — loads the measured impulse responses,
   then runs the real-time FxNLMS loop: records a baseline (no cancellation)
   phase, then an active ANC phase, adapting the filter weights live. Saves
   raw audio (`mics_raw.wav`, `ref_noise.wav`, `err_noise.wav`, `y_cancel.wav`).
3. **`pipeline/presentation_graphics.m`** — loads those recordings and
   generates the four summary figures (time domain, frequency domain,
   spectrogram comparison, performance dashboard).

**Hardware setup:** Behringer UMC404HD (or similar) used for both input and
output (This was a last minute change, if not working use older files listed below). Reference mic on input channel 1, error mics on the remaining input
channels. Cancellation speakers on 2 output channels. Device auto-detection
in the scripts matches on device name substrings (e.g. `"in 1-4 (behringer"`)
— update these strings if you're on different hardware.

**Requires:** MATLAB Audio Toolbox.

## Other folders

- **`calibration/`** — one-off hardware bring-up tools: `speaker_test.m`
  (maps output channels to physical speakers) and `anc_delay_test.m`
  (measures acoustic round-trip delay via cross-correlation). Not part of
  the regular run pipeline.
- **`simulation/`** — the original offline algorithm validation done in
  Simulink (`FxLMS_Sys.slx`, `FxLMS_Sys_FB.slx`) before any real hardware
  was used, plus the script (`FxLMS_algo_sim.m`) that prepared measured
  impulse responses (`C Feb 5.wav`, `L Feb 5.wav`) into FIR taps for it.
- **`legacy/`** — earlier, superseded versions of the full system, kept for
  history:
  - `Full_system_v1_singlemic_sonyAVR.m` — first real-time version: single
    reference/error mic, output through a Sony AVR's 7.1 HDMI channels.
  - `Full_system_v2_intermediate.m` — intermediate version between v1 and
    the current system.
  - `diagnose_anc.m` — a diagnostic checklist script from the v1 era (its
    input recordings under `Recordings/` no longer exist, so it won't run
    as-is; kept for reference).
  - `IRs_verified.mat`, `Spath_L_feb_09_1.wav`, `Spath_R_feb_09_1.wav` —
    secondary path measurements used by v1.
  - `Pictures/` — dated tuning-run snapshots (`30-01-20k_Test` through
    `04-02-5k_Multi_Test`) from the v1/v2 era, each with its own raw
    recordings, generated figures, and the exact `presentation_graphics.m`
    variant used for that run.
- **`results/`** — output of the current system: `latest/` (most recent
  full run) and dated multi-mic/multi-speaker test folders (`2 spk 1 mic`,
  `2 spk 2 mic`), each keeping the recordings, generated figures, and the
  `presentation_graphics.m` variant used to produce them.
- **`docs/`** — `Mic_Specs.pdf` reference datasheet.

## Note on data files

Raw recordings (`*.wav`) and MATLAB data files (`*.mat`) are intentionally
**not tracked in git** (see `.gitignore`) — they're large and regenerated by
running the pipeline. They still exist locally in `pipeline/`, `results/`,
`legacy/`, and `simulation/`; share the full folder (e.g. via Teams/OneDrive)
if someone needs the actual audio, not just the code.
